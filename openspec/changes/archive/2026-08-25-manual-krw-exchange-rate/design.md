## Context

비용 집계는 현재 Costs API 응답의 `amount.value`만 사용하며 통화 코드를 버리고, 메인 화면과 위젯은 각자 `$` 문자열을 붙인다. 두 WebView는 같은 Tauri Store를 읽을 수 있다.

## Goals / Non-Goals

**Goals:**

- 원본 비용의 통화와 USD→KRW 수동 환율을 명시적으로 모델링한다.
- 메인 화면과 위젯이 하나의 포매팅 규칙과 저장 키를 사용하게 한다.
- 네트워크 의존 없이 결정 가능한 KRW 환산액을 제공한다.

**Non-Goals:**

- 환율 API 연동, 자동 갱신 또는 과거 환율 적용
- USD 외 통화의 KRW 변환
- 청구서 금액 또는 세금을 재계산하는 기능

## Decisions

### 1. 원본 금액을 기준값으로 유지한다

Rust 응답에 Costs API의 통화 코드를 포함하고, 프런트엔드는 원본 금액을 변환하지 않는다. USD에만 KRW 보조값을 계산한다. 환산액만 반환하는 방식은 원본 청구 금액을 잃고 통화가 바뀔 경우 오표시할 수 있다.

### 2. 수동 환율은 Tauri Store에 저장한다

`tokenglass_usd_to_krw_rate` 키에 양수 숫자를 저장하며, 설정이 없거나 손상된 경우 1,350을 사용한다. 기존 API 키와 같은 사용자별 설정 저장소를 재사용해 백엔드 상태나 별도 영속 계층을 만들지 않는다.

### 3. 공통 프런트엔드 포매터를 둔다

`usage.ts`가 원본 통화 포맷, USD→KRW 변환, 환율 검증을 제공한다. App과 Widget은 이 결과를 렌더링만 하므로 표기와 반올림이 일치한다. `Intl.NumberFormat`을 사용해 USD 소수점과 KRW 정수 그룹화를 현지화한다.

## Risks / Trade-offs

- [수동 환율이 시장 환율과 달라질 수 있음] → 적용 환율을 화면에 함께 표시하고 API 연동으로 오인되지 않게 한다.
- [API가 USD 외 또는 혼합 통화를 반환할 수 있음] → 통화를 응답에 보존하고 USD가 아닌 경우 환산하지 않는다.
- [잘못된 저장값] → 로드·저장 시 양수 유한 수를 검증하고 기본값으로 폴백한다.

## Migration Plan

1. Costs 응답 계약에 통화 코드를 추가하고 기본 USD를 적용한다.
2. 공통 환율·포매팅 함수를 추가한 뒤 두 화면을 전환한다.
3. 설정 저장, 유효성 검사, 메인 및 위젯 반영을 검증한다.

롤백 시 신규 설정 키는 무시해도 기존 API 키 및 사용량 동작에 영향이 없다.
