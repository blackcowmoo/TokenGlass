## Why

메인 대시보드와 데스크톱 위젯이 OpenAI Usage/Costs API를 독립적으로 호출해 중복 요청이 발생하고, 갱신 실패 시 마지막으로 성공한 데이터까지 사라진다. 앱 실행 중에는 공유 캐시와 일관된 갱신 정책을 적용하고, 사용자가 데이터의 실제 최신 성공 시각을 확인할 수 있어야 한다.

## What Changes

- OpenAI API 사용량 결과를 앱 프로세스 내에서 공유하는 메모리 캐시를 추가한다.
- 앱 시작 시 최신 사용량을 조회하고, 실행 중에는 5분 주기로 자동 갱신한다.
- 메인 대시보드와 위젯의 동시 요청을 하나의 네트워크 갱신으로 통합한다.
- 사용자가 요청하는 수동 새로고침은 캐시 유효 기간과 관계없이 네트워크 갱신을 수행한다.
- 마지막 API 조회 성공 시각과 캐시/네트워크 응답 상태를 화면에 표시한다.
- 자동 갱신에 실패하면 현재 앱 실행 중 마지막으로 성공한 데이터를 유지하면서 실패 상태를 알린다.
- API 키가 변경되면 기존 키로 생성한 캐시를 무효화한다.
- 캐시는 영속화하지 않으며, 앱 재시작 시 저장된 API 키를 사용해 최신 데이터를 다시 조회한다.

## Capabilities

### New Capabilities

- `openai-usage-refresh`: OpenAI 사용량의 프로세스 내 공유 캐시, 자동/수동 갱신, 마지막 성공 시각 및 실패 시 데이터 유지 동작을 정의한다.

### Modified Capabilities

없음.

## Impact

- `src-tauri/src/lib.rs`의 OpenAI 사용량 조회 명령, 공유 상태 및 응답 계약
- `src/App.tsx`의 초기 조회, 자동/수동 갱신 및 상태 표시
- `src/Widget.tsx`의 공유 캐시 사용과 자동 갱신 동작
- OpenAI Usage/Costs API 호출 빈도와 오류 처리
- Rust 단위 테스트 및 프런트엔드 갱신 상태 테스트 경계
