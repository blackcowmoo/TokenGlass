## Purpose

OpenAI 사용량을 여러 앱 화면에서 중복 호출 없이 최신 상태로 제공하고, 갱신 시각과 실패 상태를 사용자가 신뢰할 수 있도록 일관된 갱신 동작을 정의한다.

## ADDED Requirements

### Requirement: 앱 실행 중 사용량 캐시 공유
시스템은 메인 대시보드와 데스크톱 위젯이 동일한 API 키로 조회한 OpenAI 사용량을 앱 프로세스 내에서 공유해야 하며(MUST), 성공한 결과를 5분 동안 최신 캐시로 취급해야 한다(MUST).

#### Scenario: 유효한 캐시 재사용
- **WHEN** 동일한 API 키에 대한 마지막 성공 조회 후 5분이 지나기 전에 메인 대시보드 또는 위젯이 사용량을 요청한다
- **THEN** 시스템은 추가 OpenAI API 호출 없이 캐시된 결과와 원래의 마지막 성공 시각을 반환해야 한다

#### Scenario: 동시 갱신 요청 통합
- **WHEN** 동일한 API 키를 사용하는 둘 이상의 화면이 캐시가 없는 상태 또는 만료된 상태에서 동시에 갱신을 요청한다
- **THEN** 시스템은 하나의 OpenAI API 갱신만 수행하고 그 결과를 모든 요청자에게 제공해야 한다

### Requirement: 앱 시작 시 최신 데이터 조회
시스템은 OpenAI 사용량 캐시를 앱 종료 이후까지 영속화하지 않아야 하며(MUST), 앱이 새로 시작되면 저장된 API 키로 최신 사용량을 조회해야 한다(MUST).

#### Scenario: 저장된 API 키가 있는 앱 시작
- **WHEN** 저장된 OpenAI 조직 관리자 API 키가 있는 상태에서 애플리케이션이 새로 시작된다
- **THEN** 시스템은 이전 실행의 결과를 복원하지 않고 OpenAI API에서 최신 사용량을 조회하여 표시해야 한다

#### Scenario: 앱 시작 조회 실패
- **WHEN** 새로 시작된 애플리케이션의 최초 OpenAI API 조회가 실패하고 현재 실행에서 성공한 데이터가 없다
- **THEN** 시스템은 사용량을 오래된 데이터로 대체하지 않고 조회 실패 상태를 표시해야 한다

### Requirement: 자동 및 수동 갱신
시스템은 저장된 API 키가 있는 동안 OpenAI 사용량을 5분 주기로 자동 갱신해야 하며(MUST), 사용자의 수동 새로고침 요청은 기존 캐시의 유효 여부와 관계없이 네트워크 갱신을 시작해야 한다(MUST).

#### Scenario: 주기적 자동 갱신
- **WHEN** 마지막 성공 조회 후 5분이 경과하고 애플리케이션이 실행 중이다
- **THEN** 시스템은 OpenAI API에서 사용량 갱신을 시도해야 한다

#### Scenario: 만료 후 화면 재표시
- **WHEN** 메인 대시보드가 숨겨져 있는 동안 캐시가 만료되고 사용자가 대시보드를 다시 표시한다
- **THEN** 시스템은 다음 정기 주기를 기다리지 않고 사용량 갱신을 시도해야 한다

#### Scenario: 수동 강제 새로고침
- **WHEN** 사용자가 새로고침 동작을 요청한다
- **THEN** 시스템은 유효한 캐시가 있더라도 OpenAI API에서 최신 사용량 갱신을 시도해야 한다

### Requirement: 마지막 성공 시각 표시
시스템은 실제 OpenAI Usage/Costs API 조회가 모두 성공한 시각을 마지막 성공 시각으로 기록하고 사용자에게 표시해야 한다(MUST). 캐시를 읽거나 갱신에 실패한 동작은 이 시각을 변경하지 않아야 한다(MUST).

#### Scenario: 네트워크 갱신 성공
- **WHEN** OpenAI Usage API와 Costs API 조회가 모두 성공한다
- **THEN** 시스템은 해당 성공 시각을 결과와 함께 기록하고 메인 대시보드에 표시해야 한다

#### Scenario: 캐시 결과 표시
- **WHEN** 화면이 캐시된 사용량을 수신한다
- **THEN** 시스템은 화면이 캐시를 수신한 현재 시각이 아니라 캐시에 기록된 마지막 성공 시각을 표시해야 한다

### Requirement: 갱신 실패 시 마지막 데이터 유지
시스템은 현재 앱 실행 중 성공한 사용량이 있는 상태에서 후속 갱신이 실패하면 해당 데이터를 유지하고, 마지막 성공 시각과 갱신 실패 상태를 함께 알려야 한다(MUST).

#### Scenario: 자동 갱신 실패
- **WHEN** 현재 실행에서 성공한 사용량을 표시하던 중 자동 갱신이 실패한다
- **THEN** 시스템은 기존 사용량과 마지막 성공 시각을 유지하고 갱신 실패 상태를 표시해야 한다

#### Scenario: 수동 갱신 실패
- **WHEN** 현재 실행에서 성공한 사용량을 표시하던 중 사용자가 요청한 강제 갱신이 실패한다
- **THEN** 시스템은 기존 사용량을 지우지 않고 오류와 마지막 성공 시각을 표시해야 한다

### Requirement: API 키별 캐시 격리
시스템은 OpenAI 조직 관리자 API 키별로 캐시 결과를 격리해야 하며(MUST), 저장된 API 키가 변경되면 이전 키의 캐시를 새 키의 결과로 제공하지 않아야 한다(MUST).

#### Scenario: API 키 변경
- **WHEN** 사용자가 기존 값과 다른 OpenAI 조직 관리자 API 키를 저장하고 동기화를 요청한다
- **THEN** 시스템은 이전 키의 캐시를 사용하지 않고 새 키로 OpenAI API 조회를 수행해야 한다
